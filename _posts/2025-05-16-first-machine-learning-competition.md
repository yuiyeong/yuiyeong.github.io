## 📝 나는 내 학습 목표를 달성하기 위해 무엇을 어떻게 했는가?

프로젝트를 시작하며 나는 두 가지 핵심 학습목표를 세웠다.

_**ML 프로젝트의 전체 파이프라인 경험하기**_

_**효과적인 팀 협업 환경 구축하기**_

이러한 목표를 달성하기 위해 팀장(!)으로서 다음과 같은 활동을 진행했다.

- Python 프로젝트 환경 구축을 위해 Poetry, Ruff 등 최신 도구를 적용했다.
- Git 기반 협업을 위한 이슈 관리, PR 검토 프로세스를 체계화했다.
- 아파트 가격에 영향을 미치는 요소들에 대한 도메인 지식을 학습했다.
- 팀원 모두가 처음 접하는 ML 모델링 프로젝트임을 감안하여, 모든 팀원이 데이터 전처리와 피처 엔지니어링을 골고루 경험할 수 있도록 작업을 분배했다.
- 정기적인 미팅(5/7, 5/9, 5/12 이후는 매일)을 통해 지식 공유와 문제 해결 방향을 함께 모색했다.
- 팀원들의 진행 상황에 맞춰 계획을 유연하게 조정했다.

## 🤝 나는 어떤 방식으로 팀으로서 대회를 참여하는 방식을 개선했는가?

- **통합 환경 구축**: 각 팀원의 전처리 코드를 효과적으로 통합할 수 있는 함수 구조를 설계했다.

```python
def convert(df: pd.DataFrame, columns: list[str]) -> pd.DataFrame:
    # 전처리, 파생 변수 등 인코딩 과정
    return pd.DataFrame({...})
```

### 간소화된 접근법의 효과

흥미롭게도, 팀원들이 전처리하고 파생 변수를 만든 것을 합치고 인코딩한 뒤 학습시킨 모델보다, 내가 아래 8개 feature 만 가지고 Random Forest 를 학습시킨 모델이 더 좋은 점수를 받았다.
- 변수 8개
	- h3_index(one-hot encoding)
	- 층
	- 전용면적
	- 계약연월
	- 계약일
	- 건축연도
	- 주변 버스정거장 개수
	- 주변 지하철역 개수

더 놀라운 것은 전처리를 하나도 하지 않고 LightGBM을 사용했을 때 가장 좋은 점수를 받았다는 점이다. 
이는 머리가 띵!한 경험이었다.

## 💡 내가 한 행동의 결과로 어떤 지점을 달성하고, 어떠한 깨달음을 얻었는가?

- **협업 플랫폼 구축**: GitHub과 Notion을 활용한 협업 환경 구축으로 팀원 간 원활한 정보 공유가 가능했다.
- **체계적인 프로젝트 관리**: 명확한 디렉토리 구조와 코드 스타일 가이드를 통해 일관된 개발 환경을 유지할 수 있었다.
- **실무적 한계 경험**: 이론적인 ML 지식과 실제 프로젝트 적용 사이의 간극을 경험하면서, 데이터 전처리와 베이스라인 모델 구축의 중요성을 깨달았다.

핵심 깨달음은 "ML 프로젝트에서 완벽한 모델보다 견고한 파이프라인이 더 중요하다"는 점이다.
아무리 좋은 모델도 train/test 데이터셋의 불일치나 전처리 오류에 취약할 수 있음을 경험했다.

## 🔍 마주한 한계는 무엇이며, 아쉬웠던 점은 무엇인가?

**기술적 한계**
- Test 데이터셋 분석 부재로 인한 실행 오류: LabelEncoder, RandomForestClassifier 등을 활용한 결측치 처리가 새로운 데이터셋에서 문제를 일으켰다.
- Target 변수 분석 부족: 목표 변수에 대한 충분한 EDA가 이루어지지 않았다.
- Validation 전략 미비: 적절한 validation set 구성이 이루어지지 않았다.

**프로젝트 관리 측면**
- 시간 배분의 문제: EDA와 피처 엔지니어링에 너무 많은 시간을 투자하여 모델링 단계가 촉박했다.
- 베이스라인 코드 후순위화: 초기에 베이스라인 코드를 구축하지 않고 복잡한 전처리에 집중한 것이 아쉬웠다.

**협업에서 아쉬웠던 점**
- 모든 팀원이 머신러닝 경진대회가 처음이다 보니, 전체 프로세스를 이해하고 역할을 나누는 데 많은 시간이 소요되었고, 그만큼 모델 실험이나 결과 해석에 충분한 시간을 쓰지 못한 점이 아쉬웠다.
- 개인적으로 더 적극적인 방향 제시가 필요했다. 멘토링에서 받은 조언("target부터 분석", "validation set을 찾는 것이 중요")을 더 일찍 적용했다면 더 나은 결과를 얻었을 것이다.

## 🚀 한계/교훈을 바탕으로 다음 경진대회에서 시도해보고 싶은 점은 무엇인가?

1. **체계적인 시간 배분**
    - 초반 10%: Validation set 설정 및 Baseline 모델 구축
    - 중반 70%: EDA 및 Feature Engineering 집중
    - 후반 20%: 다양한 모델 실험 및 앙상블

2. **데이터 분석 순서 개선**    
    - Target 변수부터 분석 시작
    - Train/Test 데이터셋 모두 충분히 분석
    - 데이터 분포 기반의 결측치 처리 전략 수립

3. **신속한 피드백 루프 구축**    
    - 빠른 제출을 통한 베이스라인 확립
    - 리더보드 점수를 기반으로 한 점진적 개선
    - K-fold 검증을 통한 모델 안정성 확보

4. **고급 기법 적용**    
    - Pseudo Labeling 시도
    - SHAP, Permutation Feature Importance를 활용한 피처 선택
    - 앙상블 기법 적극 활용

5. **실무와 대회의 균형점 찾기**    
    - 빠른 피드백 중심의 접근
    - 도메인 지식을 적극 활용한 분석
    - Unseen 데이터 일반화를 위한 실험

이번 경진대회에서의 교훈을 바탕으로, 이론과 실전의 간극이 크고 실전에서는 전략이 필요함을 깨달았다. 
**하지만 목표를 지켰다는 점이 가장 중요하다!!!**
한 팀의 팀장이 되어 팀과 함께 첫 대회를 참여한 것이 매우 재미있는 경험이었다.

향후에는 프로젝트 초반에 전체적인 흐름과 목표를 명확히 정하고, baseline 코드 구축 및 전체 데이터에 대한 분석을 먼저 진행한 후 개별 작업을 분담하는 방식으로 더 체계적으로 협업을 이어갈 계획이다.
